API changes by version

What changed in the API in each release, newest first. Every change since the API first shipped in 1.1.0 has been additive, so an addon built against an older release keeps running on a newer one.

1.2.5

  • ActionSetting has a new constructor, ActionSetting(String label, int color, Runnable action), which tints the row's label in the HUD editor's context menu with an ARGB color; 0 keeps the default. Use it to mark a row that opens something rather than changing a value.
  • HudModule.drawText and textWidth always use the vanilla font, now that the bundled HUD fonts are gone.
  • EymHudFonts stays in place, deprecated, with every method answering vanilla, so addons that call it keep running.

1.2.4

No API changes.

1.2.3

No API changes. This is the release that moved to Minecraft 26.3, so an addon built against it targets 26.3 too, with the plain implementation configuration.

1.2.2

  • ComboHeatmap.of understands the new Custom Heatmap Difficulty and returns the player's own three tiers, read from the config on every call and kept in order.
  • ComboStreakEvent follows counted hits. With the new Hit Detection on Server, its default, the event fires once the server confirms the hit rather than when the attack is sent.

1.2.1

No API changes.

1.2.0

The largest API release. Every addition has a default, so 1.1.0 addons run unchanged.

  • HudModule implements the new IHudElement interface. getSubElements() lets a module hand the editor parts to drag one at a time, and onPositionUpdated() is called when a move finishes.
  • Fading: supportsFade(), col(int) and renderAlpha.
  • Text helpers that follow the Text Outline setting: drawText and textWidth.
  • Plugin state: saveState() and loadState() carry an addon's settings through simplecps.json, presets, share codes and server configs.
  • The settings screen gives every module a page. getSettingsScreenSettings() adds rows only there, and getSettingsTabs(), with the new SettingsTab record, splits the page into tabs.
  • Live preview: getPreview(), isPreviewing() and the new HudPreview interface.
  • Events: EymistakenHudPlugin.registerEvents(), EymistakenHudEventBus, ComboStreakEvent and ComboHeatmap.
  • HudModuleManager.registerModule() refuses a name that is already taken, and isNameTaken(String) checks first.

1.1.1

No API changes.

1.1.0

The API ships: HudModule with its eight abstract methods and the editor hooks, the six setting types, EymistakenHudPlugin and the eymistaken_hud entrypoint.
