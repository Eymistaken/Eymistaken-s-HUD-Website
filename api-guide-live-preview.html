Settings

Live preview

Settings that change how something looks are miserable to tune blind. Opt in, and the top of your page's right-hand column carries a PREVIEW card: your module, drawn live at the size it will really be.

The card sits on a checkerboard that shows transparency for what it is, and edits land in it the same frame. A focus button in its header expands it over the rest of the screen when a module is too big to judge in a sidebar.

Opting in

Nothing appears until you opt in. getPreview() returns null by default, and a null preview means no card at all rather than an empty one: the INFO, PRESETS and SHARE cards move up to fill the space.

The module drawing itself

You will rarely implement it by hand. Most previews are the module rendering exactly as it always does, with stand-in values for data the game is not producing: no clicks have been counted, no server is connected, and since the settings screen opens from the title screen too, there may be no player or world at all. HudPreview.ofModule wires up the module's own render path, and isPreviewing() is where you substitute the data:

The detail that matters is rows() feeding both the render path and the measurement. isPreviewing() is true for the whole pass, sizing included, precisely so the two agree: report one size and draw another, and the card is built for something it never shows.

The card owns the geometry. It measures you, sizes itself, centers you, applies the transform that puts one of your pixels on one real screen pixel, and clips you to the box, so render draws from the origin and never translates or scales itself. The card grows downward to fit and stops before it would push the panels below it off screen. It never widens, and a module wider than the column is clipped rather than shrunk, because a preview scaled to fit would answer the wrong question about how much room your module takes. Focus mode shows the rest.

Never step animation state the live HUD reads. With the settings screen open in game your module is drawn twice a frame, once on the real HUD and once in the preview, so any per-frame counter advanced inside your render path runs at double speed while the menu is up. Keep a preview-local copy, or leave the counter alone while isPreviewing(). The built-in keystrokes module holds separate squish and ripple maps for exactly this reason.

getPreview() is called once a frame while your page is open, so keep it cheap, and prefer handing back a cached instance to building one per call. Anything that throws, whether the getter, either size or the drawing, costs you the preview for that frame and nothing else. Like every other hook here it is additive and defaults to nothing, so an addon built against an older release keeps running, simply without a card.
